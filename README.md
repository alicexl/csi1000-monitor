# 中证1000 Roll Yield Monitor

监控中证1000指数估值分位 + IM 股指期货展期收益（roll yield）+ MO 股指期权增厚分析，为**纯多头吃贴水**策略提供每日入场/平仓/切换信号。

**定位：策略执行与监控工具，不是回测验证过的量化策略。** 它每天判断"当前是否满足策略假设"、监控这些假设有没有失效、在假设成立时给出执行信号。至于"这套策略未来能否跑赢市场"——[§二 验证边界](#二-验证了什么-什么还没验证)坦率说明。

整个项目回答一个问题：**今天该买、该卖、还是该等？**

---

## 一、它在解决什么问题

中证 1000 是 A 股 1001-1800 名的小盘股指数。**IM 期货**是中金所跟踪该指数的股指期货。

**核心观察**：IM 期货曲线通常处于 **backwardation（近月贵、远月便宜）**——远月合约比近月更深贴水。每展期一次（卖近月、买远月），"卖贵买便宜"赚到一份价差，这就是策略的本质收益——**展期收益（roll_yield）**，不是单合约对现货的绝对贴水。（"通常"而非"长期"：IM 2022-07 上市以来 4 年样本多为 back，但这是经验假设，见 [§二 验证边界](#二-验证了什么-什么还没验证)）

```
roll_yield = (当月价 − 下月价) / 当月价 = 展期一次收益率（价格是否 back）
           > 0  → 价格 backwardation（下月比当月便宜），展期能吃价差
           ≤ 0  → 价格 contango/平水（下月不再更便宜），展期反向亏钱
```

**关键看绝对价格是否 backwardation，不是单合约年化贴水。** 反例：当月年化贴水 +8%、下月 +5%，年化斜率虽为 −3%，但下月到期更晚，绝对价格通常仍低于当月（仍是 back），展期照样赚价差——**年化斜率 ≤ 0 ≠ 价格 contango**。只有当下月价格 ≥ 当月价格（真 contango/平水）时展期才反向亏钱。

但不是无脑多头。两个风险：

1. **估值过高时买入** → 指数本身下跌把展期收益亏光
2. **价格双段 contango**（当月→下月、当月→下季均 <0，下月/下季都不再比当月便宜）→ 展期收益消失甚至反向，策略前提失效

所以策略是：

> **估值低（PE/PB 历史分位都 <50%）且价格 backwardation（roll_yield > 0）时买；估值过高（>85%）或展期双段 contango（当月→下月<0 且 当月→下季<0）时卖。**

本项目每天跑一次，自动告诉你今天该怎么操作。

## 二、验证了什么，什么还没验证

**阅读本 README 时请区分两类表述**：标记为「已验证」的是客观计算，任何人用同一数据源都能复现；其余都是经验假设或策略设计，需要独立评估。

### 验证状态总览

| 内容 | 性质 |
|---|---|
| PE/PB 分位计算（ECDF count-based，§9.1） | ✅ 已验证（客观计算） |
| 当日 roll_yield 正负、基差、年化贴水 | ✅ 已验证（客观计算） |
| BS 期权定价 / IV 反推（§8 卖 Call 增厚面板） | ✅ 已验证（数学公式） |
| IM 长期以 backwardation 为主（策略前提） | ⚠️ 经验假设 |
| 估值分位 <50% 是最佳入场阈值 | ⚠️ 经验规则（未优化验证） |
| 双段 contango 才离场 | 🎨 策略设计（有解释，非数据结论） |
| 1σ OTM call 增厚长期为正 | ⚠️ 经验规则（未验证） |
| 策略长期超额收益 | ❌ 尚未验证 |

### 验证边界（坦率声明）

**IM 期货 2022 年 7 月才上市**，期限结构历史不足 4 年；PE/PB 历史约 11 年，完整牛熊周期有限。因此本项目**不做**以下宣称：

- **策略长期跑赢市场**——没有足够样本证明"吃贴水"具有稳定超额收益；
- **阈值是最优的**——PE<50% / PB<50% / PE>85% 是经验阈值，未做过参数优化或敏感性分析；
- **backwardation 会持续**——"IM 长期以 back 为主"是 4 年样本上的经验观察，可能随市场结构变化而消失（这正是每天监控 roll_yield 的原因）。

**本项目旨在提供纪律化的执行框架**：在策略假设成立时给出执行信号、在假设失效时提示离场，而不是通过有限历史样本证明策略具有稳定超额收益。

## 三、核心概念

| 概念 | 例子 | 含义 |
|---|---|---|
| **PE_TTM** | 30.6 | 滚动市盈率，越低越便宜 |
| **PE/PB 分位** | 71.9% | 当前 PE/PB 在历史样本里的排位（0%=最便宜，100%=最贵）|
| **BPS** | 3143 | close/pb ≈ 隐含净资产 B，剥离估值周期只留净资产增长（附录方法论用）|
| **基差** | -49.2 点 | 期货收盘 - 现货收盘；**负值=贴水**（期货便宜）|
| **年化贴水** | +7.2% | 把基差按剩余天数年化，便于跨合约比较 |
| **展期收益（月段）** | +0.9% | roll_yield = (当月价−下月价)/当月价（展期一次收益率），>0 价格 back 才能展期吃价差；**入场看此段** |
| **展期收益（季段）** | +3.2% | roll_yield_q = (当月价−下季价)/当月价，**离场双段判定**用（与 roll_yield 同以当月为锚）|

**合约月份规则**（CFFEX 定义）：**当月、下月、当季、下季** 共 4 个合约同时在交易。每第三个周五交割一次。

## 六、代码架构

5 个模块，**`monitor.py` 是唯一集成层**——其他 4 个模块互不 import：

```
csi1000-monitor/
├── monitor.py        ← CLI + 流水编排 + 多区间分位 + BPS 趋势回归
├── data_fetcher.py   ← akshare 拉取 + 基差/贴水/合约分类 + BS 定价/IV
├── signals.py        ← 纯算法：指标 → 7 种信号（可单测）
├── reporter.py       ← Markdown 报告 + 一行状态渲染
├── db.py             ← SQLite WAL，4 张表 CRUD
└── tests/            ← 181 个测试（单元 + E2E）
```

**为什么这么拆？** 单一调用方的模块拆分避免网状依赖：所有跨模块协调都在 `monitor.py` 里发生。`signals.py` 纯算法，输入指标输出信号，便于单测；`db.py` 只管存取；`data_fetcher.py` 只管拉数和定价；`reporter.py` 只管展示。

### 4 张 SQLite 表

| 表 | 主键 | 用途 |
|---|---|---|
| `daily_valuation` | `date` | 每日 PE/PB/收盘（2014 至今 ~2900 行）|
| `daily_contracts` | `(date, symbol)` | 每日 IM 合约行情 + 基差/贴水 |
| `signals` | `UNIQUE(date, signal_type, condition)` | 每日触发的信号（重复 INSERT OR IGNORE）|
| `position` | `id=1`（单行 CHECK 约束）| 持仓状态 |

**UPSERT 语义**：估值/合约用 `ON CONFLICT DO UPDATE`（数据源修正历史时新值覆盖）；信号用 `INSERT OR IGNORE`（同一信号一天只记一次）；持仓用 `INSERT OR REPLACE`。

## 七、`run` 命令的完整数据流

整个系统的主线：

```
[1] _scan() — 拉数据入库（幂等：DB 已是最新则跳过）
    ├─ fetch_valuation()         → akshare 拉全历史 PE/PB → UPSERT
    └─ fetch_daily_contracts()   → akshare 拉当日合约 → 分类 + 算基差 → UPSERT

[2] _generate_report() — 读 DB → 评估信号 → 写 signals 表 + 渲染报告
    ├─ _build_metrics(conn)
    │   ├─ compute_pct_for_windows()  — 多区间 PE/PB 分位（10y/5y/all）
    │   ├─ _window_median()           — PE_TTM 10 年中位数（估值回归用）
    │   ├─ _compute_bottom_trend()     — BPS 全量回归（对数趋势线 + 线性趋势 + PB 分位情景）
    │   ├─ _compute_discount_coverage() — 贴水覆盖性（持有1年展期贴水 vs PB -1σ/-2σ 跌幅）
    │   ├─ _compute_expected_return() — 持仓预期收益三因子（ROE+分红+估值变动）
    │   ├─ fetch_otm_call()           — 实时拉期权算 BS 增厚
    │   └─ → {pe_ttm, pe_ttm_pct, pb_pct, roll_yield, bottom_trend, discount_coverage, expected_return, contracts, otm_call, ...}
    │
    ├─ _extract_signal_metrics()
    │   抽出 signals 需要的 6 个数：pe_ttm_pct_10y / pb_pct_10y /
    │   current_month_discount / current_month_days / next_month_discount / roll_yield
    │   （roll_yield 是策略判断主指标，pe/pb_pct_10y 是 entry 估值条件）
    │
    ├─ evaluate(state, metrics, thresholds)  → 返回 Signal 列表
    ├─ 写入 signals 表
    └─ generate_report()  → reports/csi1000_YYYY-MM-DD.md
```

**幂等设计**：`cmd_run` 先查 DB 最新估值日期，如果 ≥ 目标交易日（周末回退到周五）则跳过拉取，直接读 DB 离线生成报告。你可以反复跑 `run`，不会重复拉数据。

## 八、信号体系（持仓 + 空仓）

策略根据 `position.status` 走**空仓侧**或**持仓侧**分支。**入场看单段展期收益（roll_yield = (当月价−下月价)/当月价 = 价格是否 back）；离场看双段（当月→下月 + 当月→下季，均<0 才算展期失效）**，单合约年化贴水仅作展示参考：

| 持仓 | 信号 | priority | 触发条件 |
|---|---|---|---|
| 空仓 | `entry` | 2 | 三条件全满足：PE<50% **且** PB<50% **且** roll_yield>0 |
| 空仓 | `warn_entry` | 4 | 部分条件满足但未全达标（列出 PE/PB/roll 三条件 ✓/✗ 缺口）|
| 空仓 | `wait` | 5 | 兜底（其他情况）|
| 持仓 | `reduce` | 1 | PE>85% **或** 展期双段<0（当月→下月<0 **且** 当月→下季<0，双段 contango 才算失效；双触发都展示）|
| 持仓 | `warn_reduce` | 4 | PE 75-85% |
| 持仓 | `switch` | 3 | 当月剩余 <7 天，该换月 |
| 持仓 | `hold` | 5 | 兜底（继续持有；含近月 contango 但远月仍 back 的中间态）|

**entry 三条件的逻辑**：PE/PB 分位管价格端（PE 看盈利、PB 看资产），roll_yield 管展期收益。三条件全满足才入场，任一不达标 fall through 到 warn_entry/wait。

> **BPS 趋势线不参与入场判断**：BPS = close/pb 是净资产（价格被分子分母抵消），其偏离趋势线反映的是**盈利周期**（盈利好坏/减值/调样），不是估值便宜/贵。"BPS 低于趋势线"更可能是基本面恶化而非低估待涨。故 BPS 回归仅作附录的"净资产底抬升"方法论证明，不进入场条件。下行保护改由「贴水覆盖 -1σ」量化（见 §9.6/§9.7）。

#### 开仓信号检查面板（空仓专属）

空仓时报告在「信号」之后、估值面板之前插入「**开仓信号检查**」面板，把入场三条件逐条对照展示：

| 条件 | 当前 | 门槛 | 达标 |
|---|---|---|---|
| PE 10y 分位 | 72.1%（观望区） | <50% | ✗ |
| PB 10y 分位 | 36.5%（入场区） | <50% | ✓ |
| 展期收益 roll_yield | +0.9% | >0 | ✓ |

分位区间标签：**入场区**(<50%) / **接近区**(50-60%) / **观望区**(60-75%) / **偏高区**(75-85%) / **过高区**(≥85%)。末行给结论「✅ 符合开仓信号」或「❌ 未达开仓（N/3 满足）」。持仓状态不展示此面板。

#### 平仓信号检查面板（持仓专属）

持仓时报告在「信号」之后、估值面板之前插入「**平仓信号检查**」面板，把平仓两条件逐条对照展示（与开仓面板位置对称）：

| 条件 | 当前 | 门槛 | 触发 |
|---|---|---|---|
| PE 10y 分位 | 72.1%（安全区） | >85% | ✗ |
| 展期 当月→下月 | +0.9%（back，7136→7072） | <0 | ✗ |
| 展期 当月→下季 | +3.6%（back，7136→6876） | <0 | ✗ |

平仓 = PE>85% **或** 展期双段<0（当月→下月<0 **且** 当月→下季<0）**任一**触发即平仓（与开仓"三条件全满足 AND"相反）。展期需双段同时 contango 才算失效——单段 contango 可能只是交割噪音，不离场（走 hold 中间态）。PE 分位标签：**安全区**(≤75%) / **预警区**(75-85%) / **平仓区**(>85%)。末行给结论「⚠️ 触发平仓信号（PE 过高/展期双段失效）」或「✅ 未触发平仓（继续持有）」。空仓状态不展示此面板。

#### 持仓盈亏（持仓专属）

平仓检查之后紧接着展示当前浮盈（持仓时最关心的数字前置）：

> 入场 2026-07-01 @ 6500，当前 6996，浮盈 +7.6%

入场价/日期来自 `open` 命令记录的 position，当前价用当日现货 close 近似。

#### 卖 Call 增厚面板（持仓专属）

持有 IM 多头时卖 **1σ OTM call** 收权利金增厚。行权价按 **ATM 隐含波动率**算 1 个标准差取：`target_strike = spot×(1+atm_iv×√T)`，再取期权链最近的 strike——IV 变化时 strike 自动伸缩，**行权概率始终标准化在 ~16%**（1σ 单尾）。

面板字段：执行价 / 实际≈σ / **ATM IV**（算 1σ 的基准，取最接近 spot 的有卖价 strike 反推）/ 权利金（点 + 元/张，乘数 200）/ 年化增厚（`(权利金/spot)×(365/天数)`，名义口径）/ 行权概率（`N(d2)`）/ 盈亏平衡 / 持仓量。

### 信号冲突解决

`evaluate()` 有后处理过滤——**兜底信号（wait/hold）只在没有任何具体动作时才展示**：

- 空仓触发 `entry` / `warn_entry` → 过滤掉 `wait`（避免"建议入场 + 继续等待"矛盾）
- 持仓触发 `reduce` / `warn_reduce` / `switch` → 过滤掉 `hold`

## 九、几个关键的设计细节

### 1. 估值口径与分位算法

#### 数据源（akshare → 乐咕乐股 legulegu.com）

| 字段 | akshare 接口 | 中文列名 → 项目字段 |
|---|---|---|
| PE_TTM | `stock_index_pe_lg("中证1000")` | "滚动市盈率"（加权）→ `pe_ttm` |
| PB | `stock_index_pb_lg("中证1000")` | "市净率"（加权）→ `pb` |

每日一行，2014-10 至今约 2857 行。项目只取**加权值**（乐咕的加权算法偏低于 Wind/中证官网，但分位算法自洽，对策略判断无影响）。

#### 分位算法（ECDF count-based）

`percentile()` 用经验分布函数：**过去 N 天里估值 ≤ 当前的交易日比例**。抗离群点（2015/2024 极值不污染）、不假设分布，与 wind/choice/雪球口径一致——不用 min-max 区间法（会被历史极值如 PE=114 扭曲：同样本 count-based 61% vs min-max 仅 14%）。

#### 三个窗口

| 窗口 | 天数 | 用途 |
|---|---|---|
| **10y** | 3652 天 | 主判断窗口（信号阈值 PE<50% / PE>85% 都基于此）|
| **5y** | 1826 天 | 近 5 年视角（注册制后小盘股活跃期，通常分位高于 10y）|
| **all** | 不限 | 全历史（含 2015 牛市极端值，分位通常低于 10y）|

cutoff 用今日午夜（不是 `now()`），避免下午跑时把今天 00:00 的行过滤掉。

#### 样本数展示

分位展示成 `71.9% (n=2427)`；样本 < 100（约 5 个月交易日）显示 `N/A ⚠`。只设绝对阈值 `MIN_SAMPLES=100` 兜底，不框"覆盖率"（10 年预期 2440 是粗估，节假日/闰年天然波动会误导）。

### 2. 交割日标签滚动（`classify_contract`）

当 `today ≥ 本月第三个周五`（CFFEX 盘后数据，存在即已收盘）：已交割的当月合约置 `ctype=None` 被过滤、旧下月升为新当月、季度合约标签独立滚动——避免交割日跑出 `days=0 / basis 噪音` 的死合约。

### 3. PE-PB 背离

`pe_pct − pb_pct`：正值=盈利回暖已计入股价但净资产看仍不贵（盈利不兑现则转估值压力）；负值=资产定价偏贵而盈利偏弱，或盈利强劲拉低 PE。

> **反直觉陷阱**：PB 高 ≠ 净资产高。PB=P/B，**PB 高 = 单位净资产卖得贵 = B 相对 P 偏低**。

### 4. 持仓预期收益三因子模型（持仓专属）

报告中的「持仓预期收益」panel（持仓专属，持有 IM 多头时长期年化回报的拆解）把长期收益拆成三个独立分量：

```
预期年化 = ROE + 分红 + 估值变动
```

| 分量 | 计算 | 数据源 |
|---|---|---|
| **ROE** | `PB / PE_TTM` = (P/B) / (P/E) = E/B | 现有 PE/PB 反推，零新数据源 |
| **分红率** | 默认 1.0% | 中证1000 历史约 1-2%，取保守下限 |
| **估值回归** | `(pe_median_10y - pe_now) / pe_now` | 历史 PE 中位数 |

**为什么 ROE 可以这样反推？** PB = P/B，PE = P/E。PB/PE = (P/B) / (P/E) = E/B = ROE。

**展期收益不计入此 panel**（由 status_line 一行单独展示），因为展期收益随期限结构变化、难以多年预测。

展示两种预期：
- **估值不变年化** = ROE + 分红（假设 PE 保持在当前水平）；附 3 年/5 年复利
- **含估值回归 1 年预期** = 估值不变年化 + 估值回归（假设 PE 1 年内回到 10 年中位数）

**当前实测**（2026-07-23，PE_TTM=30.6, PB=2.29）：
- 估值不变年化 **+8.5%**（3 年 +27.7% / 5 年 +50.3%）
- 含估值回归 1 年 **−6.2%**（当前 PE 高于 10 年中位 26.1，有回落风险）
- status_line 显示 `展期收益 +0.9%`（= (当月价−下月价)/当月价，价格 back）

### 5. BPS 底部回归（附录：净资产底抬升的方法论证明）

**BPS = close / pb ≈ 指数隐含净资产 B**。剥离了 PE/PB 周期波动，只保留净资产复利增长。

> **本节是方法论证明，不参与信号判断。** BPS 回归证明"净资产底在缓慢抬升"，为底部研究提供基本面依据；但 BPS 偏离趋势线反映的是盈利周期而非估值便宜（见 §八），故不产出进出场信号。报告里作为**附录**（`## 附录：BPS 底部回归`）展示在所有决策面板之后。

对 2014-10（PB 数据起点）至今的**全量 BPS 点**做**对数回归** `ln(BPS) = a + b×t`，拟合"净资产增长趋势线"，证明净资产长期复利增长、底部不归零。对数回归契合净资产指数增长（R²≈0.90，远优于纯点位回归的 0.46）。

同批全量点另做**线性回归** `BPS = a + b×t` 作为绝对值口径：中证1000 近 12 年近似"每年 +105 点"线性增长（线性 R²≈0.895）。对数给年化增长率 %，线性给绝对点数/年，两者互补。

附录展示：年化增长率（对数 b×365×100）/ 线性 +N 点/年 / 当前 BPS vs 趋势拟合值（仅展示，不作判据）/ BPS 趋势图（base64 内联 PNG，未装 matplotlib 降级为无图）。

> BPS 相对自身趋势线偏离天然极小（趋势线由 BPS 拟合，循环论证），故不构成估值信号。

### 6. PB 分位情景点位（价格底视角）

固定资产 B（=close/pb），看不同 **PB 分位**对应的点位与跌幅：

| PB | 对应点位 | 跌幅 | 情景 |
|---|---|---|---|
| 2.28 | 7159 | — | 当前 |
| 2.60 | 8163 | +14% | PB 50%分位 (0σ) |
| 2.04 | 6405 | -11% | PB 15.9%分位 (-1σ) |
| 1.60 | 5024 | -30% | PB 1%分位 (-2σ) |

用历史 PB **经验分位**（而非固定 1.5/1.8）定义情景，跨周期可比。分位刻度借正态 σ 的概率语言标"出现难易程度"——经验分位本身即出现概率（15.9% = 历史仅 15.9% 时间更低 ≈ -1σ），σ 仅作直观标签，**不假设 PB 正态**（PB 右偏严重，用均值±σ 理论值会穿铁底，故取经验分位对应的实际 PB）。只取左尾低估侧（-1σ/-2σ），右尾 2015 极值无参考价值。-2σ 取 **1% 分位 ≈ PB 1.60**——2024 年双波危机（2 月/8-9 月）实测支撑区，有持续性；不用 2024-02-05 的单日极值 1.49（仅持续 1 天，属异常值）。回答："资产已便宜，但估值还有多少杀跌空间"。

> **贴水覆盖性**（本表跌幅 vs 下季贴水年限）：持有 1 年的展期贴水（按当前下季贴水线性累计，不复利）vs -1σ/-2σ 跌幅，逐格标 ✅已覆盖/❌未覆盖 + margin。贴水只看 1 年——更长 horizon 是贴水均值回归的外推，不可靠；3 年才覆盖说明下行保护不足。-1σ 是主判（常态杀跌，贴水应覆盖），-2σ 仅极端参考（黑天鹅级，不要求覆盖）。

## 十、子命令完整参考

| 命令 | 作用 |
|---|---|
| `run` | 自动判断：DB 数据是最新（≥目标交易日）则跳过拉取，否则先拉数据，再生成报告 |

| `close` | 平仓：清空持仓 |

`open`/`close` 是给用户记录**实际开仓行为**的，必须手动执行——工具不会自动下单。开仓后 `run` 会自动在报告里显示持仓盈亏（入场价 vs 当前价）。

## 十二、数据源

全部来自 [akshare](https://akshare.akfamily.xyz/)（估值口径详见 §9.1）：

| 数据 | akshare 接口 | 说明 |
|---|---|---|
| PE 历史 | `stock_index_pe_lg("中证1000")` | 乐咕乐股 8 列，项目取滚动市盈率（加权）|
| PB 历史 | `stock_index_pb_lg("中证1000")` | 乐咕乐股 5 列，项目取市净率（加权）|
| 当日合约 | `get_futures_daily(market="CFFEX")` | 筛 IM 开头 |
| 期权 | `option_cffex_zz1000_spot_sina` | MO 当月/下月期权链 |

**已知坑**：
- `stock_index_pb_lg` 第 4 列是「等权市净率」**不是**「加权市净率」 → 必须自己算分位
- `prob_above_strike` P(S_T>K) = N(d2) 不是 1-N(d2)
- 周末 / 节假日 CFFEX 当日数据返回空，工作日重试
